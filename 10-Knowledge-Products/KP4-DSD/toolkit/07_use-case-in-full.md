## How to use this blank instrument

Copy this page into your own document. Fill in the answer to every line. Do not leave a line empty: write "none" where nothing applies, and where the answer is not yet known write an open question with the name of its owner and a date. Do not guess an answer to close a question. When the document is finished, give it to the person who accepts it, together with the questions at the end of this page.

## The story

Write these in plain sentences.

| Line | What to write | Your answer |
| --- | --- | --- |
| **Scope** | The system the story is about | |
| **Who has an interest, and what** | Each stakeholder and the interest that must be protected | |
| **What is already true** | What holds when the story starts and is not checked again | |
| **What starts it** | The business event; it may be a date | |
| **What is still guaranteed if it fails** | The least the system promises | |
| **What is true when it succeeds** | It must satisfy every interest listed above | |
| **The main path** | Three to nine numbered steps, with nothing going wrong and no branches | |
| **Every way it can go wrong** | One entry for each, numbered against the step it leaves: the condition, what is done, and how it ends | |
| **Quality requirements** | Cited by their reference, not written again | |
| **How you would know it is done** | One acceptance test for the main path and one for each way it can go wrong | |

## Before you accept it

1. Could a builder follow every step without having to work anything out or ask anybody?
2. Does every way the story can go wrong have its own ending?
3. Is every interest listed at the start satisfied when the story succeeds?
4. Does every step that the main path takes refer only to records and rules that exist in the earlier documents?
5. Is every open question marked as a question, with an owner and a date, and not answered with a guess?
