# The shared groundwork: states, events, code lists and settings

The states, settings, code lists and events that every goal shares, written once. A goal that needs something that is not here raises a question and does not invent it.

| | |
| --- | --- |
| **Document of the twelve** | 6 |
| **Who writes it** | A person, with an assistant |
| **What goes in** | Document 3 |
| **Who accepts it** | The owner of each setting |
| **Taught in** | 2.5, 4.3 |

## How to use this blank instrument

Copy this page into your own document. Fill in the answer to every line. Do not leave a line empty: write "none" where nothing applies, and where the answer is not yet known write an open question with the name of its owner and a date. Do not guess an answer to close a question. When the document is finished, give it to the person who accepts it, together with the questions at the end of this page.

## One record: identity, ownership and state

Write one block for each record that has states or an owner.

| Line | What to write | Your answer |
| --- | --- | --- |
| **What one row is** | One row for each ... | |
| **When two rows are the same** | The facts that make two rows one | |
| **Who writes it** | This system, naming the act that writes it; or another body, and this system only reads | |
| **Facts written elsewhere** | Each, with its authority | |
| **Stored or worked out** | For each fact: stored, or worked out by a named computation | |
| **Deletion** | Never; or the named authority under which a row may be removed | |
| **States** | The closed set of states, the first one, and every last one | |
| **Moves between states** | For each move: from, to, what triggers it, and who may make it | |
| **Open questions** | Each with an owner and a date | |

## One code list

Write one block for each list of values that more than one goal uses.

| Line | What to write | Your answer |
| --- | --- | --- |

| **Closed or open** | Closed by law or by its issuer; or extensible, by whom | |
| **Edition in use** | How the list is versioned and where the edition in use is recorded | |
| **When a value is retired** | Rows keep the value and it stays readable; or the rows are migrated, by whom | |

## One setting

Write one block for each value that the administration may change without changing the build.

| Line | What to write | Your answer |
| --- | --- | --- |
| **Name** | The one name every reader cites | |
| **Who reads it** | Every goal, screen, rule and computation that reads it | |
| **Kind of value** | A switch; a choice from a named list; a quantity with its unit and bounds; a role; a period | |
| **Value in force and why** | The value now, and the reason: the customer's words, a ruling, or an operational reason | |
| **Authority** | A law with its section; a published policy; or this administration's decision | |
| **Who may change it, and how** | A named role, and the path | |
| **When it changes** | A change is a new version with a date; work already in flight keeps the value it was done under, or is reconsidered, as written here | |

## Before you accept it

1. Does every record with states list every state and every move, and who may make each move?
2. Does every setting name who may change it, and does its value have a stated reason?
3. Is every code list owned by a person or unit here?
4. Is every place where a goal might invent something missing covered by a question with an owner?
