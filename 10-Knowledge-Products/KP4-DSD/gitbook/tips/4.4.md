## Example input

**[your ministry]:** MoEYS, Progressa's ministry of education, youth and skills.

**[name of the goal]:** approve a change of an institution's name.

**[paste the section]:** an excerpt of the file, as written for the program:

```
list:  name_change_advice   filter: status = awaiting_minister
form:  approve_name_change
  present_name      text      source: form
  new_name          text      source: pheqa_advice   readonly
  pheqa_advice      text      source: pheqa_advice   readonly
  decision          select    options: approve | do_not_approve
  effective_date    date      default: today
on_record: send approval -> pheqa via linkup ; add to list approvals
permission: role minister
```

**[paste them]:** the agreed screens: the minister opens PHEQA's advice on changes of name that waits for a decision. The screen shows the present name, read from PHEQA's register across Linkup; the new name asked for and PHEQA's advice, as PHEQA sent them. The decision is chosen: approve or do not approve. Recording it sends the approval to PHEQA; officers of MoEYS see it in the list of approvals.

## Example output

**The section in plain sentences.** The minister starts from the list of PHEQA's advice on changes of name that waits for a decision. The screen shows the institution's present name, read from PHEQA's register across Linkup. The new name asked for and PHEQA's advice come as PHEQA sent them, and cannot be changed. The minister chooses: approve or do not approve. *Not agreed:* the screen also carries a date the change takes effect, set to the day of approval. Recording the decision sends the approval to PHEQA across Linkup and adds it to the list of approvals. Only the minister may do this.

**In the section but not in the screens**
- The date the change takes effect, set to today.
- Only the role "minister" may record the decision.

**In the screens but not in the section**
- None found.

## Reading the output

### 1. The effective date is caught

The file sets a date the change takes effect, and the screens never mention one. The run marked it in the reading and listed it. That is the same assumption the review of the model must put to the Director of Higher Education in [4.5](./4-5.md).

### 2. The reading says what was agreed, not what the file says

The file reads `present_name text source: form`: a box someone types into. The reading says the present name is read from PHEQA's register across Linkup, because it used the agreed screens' words. The difference list missed it. The file is what gets built, so this one goes to the person who approves the model, not into a corrected reading.

### 3. "Officers see it" is thinner in the file

The screens say officers of MoEYS see the approval; the file grants only the role "minister" and says nothing about who may read the list. Ask whether that was meant.

## What next

Every difference goes onto the [review of the application model](../toolkit/11_application-model-review.md), where [4.5](./4-5.md) turns each into a card the owner rules on.
