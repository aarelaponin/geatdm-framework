## The concept

This is the exchange the whole framework exists for: the examination authority issues a credential and fetches the learner's identity and enrolment itself, asking the learner once. What follows was recorded from the running federation.

This is the call on screen. The examination authority, PNEA, receives a learner's credential application. Without once-only, PNEA would ask the learner for paper proof of identity and of enrolment. With it, PNEA fetches the identity from the identity authority, PNIA, and the enrolment from the learner registry, PLR, over the bus.

First, the form before and after the call. Before, ten rows, all blank: ten questions the learner answers, and two sets of paper proof. Once PNEA has the learner's national ID, nine rows fill in: five from the identity authority, PNIA, four from the learner registry, PLR, each labelled with its source. One question asked, nine fetched.

Second, the second tab reads the exchange by layer. In the legal pane, the identity authority, PNIA, sends five fields and names three it holds but withholds: a mother's name, a birth registration number, an address. The purpose does not need them.

Third, permission. Asked the identical question, the examination authority, PNEA, is allowed, and the learner registry, PLR, is refused by the identity authority's access list. Then the operator withdraws the examination authority's permission: within seconds the identity rows are denied while the enrolment rows still fill. Restore it, and the form is whole. Being on the bus is not permission.

Fourth, the record and the proof. The exchange is written to disk as the assembled application, one line per field with its source; the national ID is the only line the citizen supplied. And the acceptance script runs the exchange as six checks: the call, the right learner, asked once, the denial, a clean not-found, and field conformance. All six pass: the technical half of go-live approval.

**WHEN** (technical): PNEA makes two calls through its own security server.

```
GET https://ss-pnea:2443/r1/PROGRESSA/GOV/PNIA/IDENTITY/identity-api/persons/{nin}
    X-Road-Client: PROGRESSA/GOV/PNEA/EXAMS
GET https://ss-pnea:2443/r1/PROGRESSA/GOV/PLR/ENROLMENT/enrolment-api/enrolments/{nin}
    X-Road-Client: PROGRESSA/GOV/PNEA/EXAMS
```

**THEN**

| # | Check | Passes when | Layer |
| --- | --- | --- | --- |
| 1 | Happy path | Both calls return 200, routed server to server (`ss-pnea` to `ss-pnia` and `ss-plr`) | technical |
| 2 | Right learner | Every returned field equals the seeded record for that NIN | semantic |
| 3 | Asked once | The assembled application holds one field from the citizen (the NIN) and nine from the bus. No field is keyed twice | organisational, legal |

| 5 | Negative | The same identity call, sent as `PROGRESSA/GOV/PLR/ENROLMENT` through `ss-plr`, is refused by PNIA's access list with an X-Road access-denied fault, not a transport error | organisational |

{% tab title="Reading the output" %}
This is the teaching part of the play. Work through the output the way a chief architect would — what is earned, what is invented, what is missing.

<details>

<summary>1. The negative check tests the right thing</summary>

PLR is a member of the bus and publishes a service of its own, so its refusal shows that the access list did the work, not membership. The script also requires the refusal to come from PNIA's side as an access-denied fault. A timeout would look like a pass but prove nothing. The build pack's acceptance file records this denial as the X-Road fault `Server.ServerProxy.AccessDenied`.

</details>

<details>

<summary>2. "Legal" on check 3 is overstated</summary>

The script builds the application file and then checks that file. That proves no field was keyed twice in this form. It does not prove the learner was not asked on paper somewhere else. Check 4 tests that the response leaves out the withheld fields, but nothing in the script can test whether the lawful basis is real, and in the pack that wording is illustrative. Call the legal layer "enforced as configured", not "proven".

</details>

<details>

<summary>3. Two cases are missing</summary>

First, a NIN that PNIA holds and PLR does not should return the identity and a clean 404 from the enrolment service. A silent empty answer must not pass. Second, a plain-HTTP call to PNEA's security server should be refused, because PNEA's connection is set to HTTPS. The pack's script runs the first case as one of its six checks. Its acceptance file records the second refusal, but the script does not test it.

</details>

{% hint style="danger" %}
**Safeguard for this play.** An acceptance check that only proves the happy path is half a check — include the negative case (an unauthorised member is denied) and confirm the data returned is the right learner's, not merely that data returned. Run it against the sandbox federation, and treat a passing check as proof for this exchange only, not a guarantee for exchanges you have not tested.
{% endhint %}
