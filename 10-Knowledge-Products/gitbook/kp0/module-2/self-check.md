# Self-check — Module 2

**Module 2 — Prepare: set up what the AI knows and can do.** Answer each question before you read the answer beside it.

Five questions, drawn from the four pages. Questions 1 and 3 are multiple choice. Questions 2, 4 and 5 ask for a short answer, which is right if it makes the point of the model answer. Four or five right means the module's point has landed; below four, read again the page named beside each question you missed. The threshold is a proposal, to be tested with the first learners.

| # | Question | Model answer | Drawn from |
| --- | --- | --- | --- |
| 1 | You have a country context pack of seven sections, about twenty pages. A tip asks only for your sector's laws. What do you paste? (a) The whole pack: more context is always better. (b) The section on laws and policy, with its date. (c) Nothing: the assistant can search for the laws. (d) A one-line summary of the pack. | (b). Give each task the smallest set of information it needs. The whole pack buries the laws among nineteen pages the task does not use; a search gives undated, unchecked results; a one-line summary loses the detail. | [2.1](2-1.md) Build the context once |
| 2 | Your unit pastes the same four paragraphs into every chat: who the unit is, what it produces, 'posts, not names', and 'list open questions at the end'. What should it do instead, and what must the result carry? | Put them once into a project's standing instructions, with the files the unit's work uses. The brief should carry who the unit is, what it produces and in what format, the standing rules, what each file is and its date, what never goes in, and who reviews it and when. | [2.2](2-2.md) Projects and standing instructions |
| 3 | Your unit checks every draft against PAERA, by section, ten times a month, always the same way. Which setup fits best? (a) A new prompt each time. (b) A project. (c) A skill that packages the check, with a connector to the published source. (d) None: do it by hand. | (c). A procedure that repeats the same way is what a skill packages, and a check against a published source needs a way to reach it. A project carries standing context, not a procedure; a fresh prompt repeats work and drifts. | [2.3](2-3.md) Skills and connectors |
| 4 | A colleague wants to add last year's roles register, which names the office-holders, and the draft cabinet paper on the Registry to the unit's project 'so the assistant knows everything'. What do you say? | No to both. The project is used by every chat in it and by everyone it is shared with. The cabinet paper is unpublished; names belong out of every setup (posts, not names). The roles register can go in by post, with its date, once it has been checked. | [2.4](2-4.md) Judgement: what never goes into the setup |
| 5 | A colleague found a skill on a public website that 'writes ministerial briefings in your style', and wants to install it for the whole unit. What do you check first, and why? | Who wrote it, and what every file in it says: read them before installing. Text inside a skill, or inside any source the assistant reads, can carry instructions the assistant follows, such as sending your material elsewhere. Install only from a source you trust, and try it first on invented material. | [2.3](2-3.md) Skills and connectors |
