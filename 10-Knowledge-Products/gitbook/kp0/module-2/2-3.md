# 2.3 Skills and connectors

> **Single message.** A skill packages a procedure you repeat; a connector lets the assistant reach a source; choose the lightest setup that does the job.

## The concept

A project carries what an assistant should know. Two other things change what it can do.

A skill is a procedure packaged with what it needs: the steps, the reference material, and the shape of the output. It sits ready, and the assistant loads it when a task calls for it, instead of you pasting the procedure each time. Each skill has a short header that says what it is for; the assistant reads only the headers until one matches the task, so many skills cost almost nothing until one is used. Skills follow an [open standard, Agent Skills](https://agentskills.io), so the same skill can run in more than one assistant.

A connector lets the assistant reach a source: a document library, a knowledge base, a register. With a connector, the assistant reads the current version of the source when it needs it, instead of a copy you pasted last month. Most connectors follow one open protocol, the [Model Context Protocol](https://modelcontextprotocol.io), MCP for short. A connector reads with the permissions of the person who uses it, so it reaches every file that person can open, including files they were given access to by mistake. The [UK government's trial of Microsoft 365 Copilot](https://www.gov.uk/government/publications/microsoft-365-copilot-experiment-cross-government-findings-report) found exactly this: the assistant surfaced files users could open but should not have.

Both bring in text that someone else wrote, and an assistant can take instructions from it. A line hidden in a web page, a shared document or a skill's files can tell the assistant to ignore your rules or send your material elsewhere. This is called prompt injection, and [the industry's security reference](https://genai.owasp.org/llmrisk/llm01-prompt-injection/) lists it as the first risk of these tools. Install skills only from a source you trust, and read their files before you do; connect only sources whose content your unit controls or trusts.

Choose the lightest setup that does the job. A task you do once is a prompt. Context the unit's work always needs goes in a project. A procedure you repeat the same way, ten times a month, is a skill. A source that changes, and must be read as it is today, is a connector. Each step up is more work to set up and more to keep current, so step up only when the lighter one is no longer enough.

This knowledge base already offers skills. The optional [ea-plays kit](../../start-here/ea-plays-kit.md) packages the procedures of some AI usage tips as skills. They bring the named source in before the draft is written, and check the draft after: every output opens with a header that counts the sources by kind and the lines nobody could verify. The tips run without the kit. With it, the source check, the step most people skip, is harder to leave out.

## In the tool

Shown in Claude.

Installing one skill. Download the ea-plays kit from its public repository, and take the folder of the one skill you want; each skill folder is complete on its own. Read its files first, and try it on invented material, such as the Progressa practice material on these pages, before your own. Make a ZIP of that folder, keeping the folder's name, which must match the skill's name. Then, in Claude, open Customize, then Skills, choose +, and upload the ZIP. Open the skill's main file and read its header: the name and the one-paragraph description are what the assistant reads to decide when to use it. If the description does not match how your unit would ask, the skill will not be used when you expect.

Connecting this knowledge base. This knowledge base is published on GitBook, and a published GitBook site offers [a connector of its own](https://gitbook.com/docs/ai-for-your-readers/mcp-servers-for-published-docs): the site's address followed by /~gitbook/mcp. Add it in the settings as a custom connector. The assistant can then search and read this knowledge base's pages as they are published today. The connector can only read.

Turning them off. Skills and connectors can be switched off in the settings, or for one chat in the tools menu. Switch off what a task does not need: fewer tools, like less context, gives a better answer.

**Where this is in each assistant:** [Claude: skills](https://support.claude.com/en/articles/12512180-use-skills-in-claude) · [Claude: connectors](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) · [ChatGPT: apps](https://help.openai.com/en/articles/11487775-apps-in-chatgpt) · [Gemini: apps](https://support.google.com/gemini/answer/14959807) · [Microsoft 365 Copilot: connectors](https://learn.microsoft.com/en-us/microsoft-365/copilot/connectors/overview)

## Worked example — A reference check, packaged and connected

*Progressa is the fictional country every course in this knowledge base uses; every body, figure and date in the example is invented. MoEYS is its Ministry of Education, Youth and Skills; PNEA its National Examinations Authority; PNIA its National ID Authority; PDGA its Digital Government Authority; and the PLR the Progressa Learner Registry it plans.*

The architecture unit of PDGA checks its papers against PAERA, GovStack's reference architecture for public administration, by section, ten or more times a month. Each analyst did it differently, and one paper cited a section that PAERA does not have.

The unit installed one skill of the ea-plays kit, the PAERA reference check, and connected this knowledge base. The next paper, a note on Progressa's data-exchange gaps, came back with the header the kit puts on every output: nine sources, seven of them primary; two lines unverified. The two lines named PAERA sections. The skill had looked each one up at its public address; one existed and one did not, and the header said which.

The unit kept the project for its standing context, the skill for the check, and the connector for this knowledge base. A one-off question about a meeting stayed a prompt.

## Your turn — Decide which tasks need a prompt, a project, a skill or a connector

{% hint style="success" %}
**💡 AI usage tip** · Decide which tasks need a prompt, a project, a skill or a connector

**Bring:** the list of the unit's tasks with an assistant, with how often each is done and what it uses.
**Get:** a table of which tasks need a prompt, a project, a skill or a connector, with the reason for each and the order to build them.
**Time:** ~15 min · **Assistant:** any; the tips are tool-neutral.
**Watch for:** A connector reaches its source from every chat.
{% endhint %}

**The problem it solves.** A unit uses an assistant for many tasks, set up anyhow. Some are pasted again every week; some reach for a source that has changed. Nobody has decided which setup each task deserves.

Copy the prompt, replace the bracketed parts with your own material, and run it in the assistant your organisation has approved. Never paste personal data or unpublished documents: see [1.4](../module-1/1-4.md).

Two routes: **practise** on the Progressa material in the second tab and check your result against the answer key, or **bring your own** material.

{% tabs %}
{% tab title="Prompt" %}
```text
Below is a list of the tasks my unit does with an AI assistant, with how often each is done and what it uses [paste the list]. For each task, recommend one of four setups: (1) a prompt, for a task done once or rarely; (2) a project, for context the unit's work always needs; (3) a skill, for a procedure repeated the same way; (4) a connector, for a source that changes and must be read as it is today. For each task produce one row with: (a) the task; (b) the setup; (c) the reason, in one line, from how often it is done, whether its steps repeat, and whether its source changes; (d) what the setup would hold. Recommend the lightest setup that does the job. Where a task would put personal or confidential data into a project, skill or connector, say so and recommend a prompt with placeholders instead. Output: a table with one row per task, then the setups in the order to build them.
```
{% endtab %}

{% tab title="Practise on Progressa" %}
*Invented for this course: every name, number and date below is fictional. Paste it where the prompt asks for your material.*

The tasks of PDGA's architecture unit with an assistant:

(1) A note on each ministry's request to join Linkup, the same steps each time: about four a month. (2) Checking papers against PAERA, by section: ten or more a month. (3) The unit's standing context, its rules and the Roadmap: needed in every chat. (4) A speech for the Director-General at a conference: once. (5) Reading Linkup's current member list, which changes every month: weekly. (6) A monthly summary of the onboarding queue, from a spreadsheet that holds officers' names and phone numbers: monthly. (7) A review of the Roadmap's progress: once a year. (8) Translating a one-page note into a local language: a few times a year.

{% endtab %}

{% tab title="Answer key" %}
*Read this after your own run. Your result will be worded differently; check that it finds the same things.*


| Task | Setup | Why |
| --- | --- | --- |
| 1, 2 | Skill | The same procedure, repeated; 2 also needs a connector to PAERA's published text |
| 3 | Project | Context every chat needs |
| 4, 7, 8 | Prompt | Done once or rarely; 8 is read by a fluent colleague before use |
| 5 | Connector | A source that changes, read as it is today; only once its owner agrees |
| 6 | Prompt, with placeholders | The spreadsheet holds names and phone numbers, so it goes into no setup |

If your table put task 6 in a project or behind a connector, the prompt's own rule was missed. Order to build: the project first, then the skill for task 1, then the connector.

{% endtab %}

{% hint style="danger" %}
**Safeguard.** A connector lets the assistant read a source in every chat that uses it, with your permissions, and what it reads can be repeated in any answer. Agree each connector with the owner of the source before you add it, whatever the table recommends.
{% endhint %}
