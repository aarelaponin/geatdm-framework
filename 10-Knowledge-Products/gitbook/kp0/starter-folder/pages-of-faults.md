# The pages of faults

## Analysis — the faults it refuses

**The kind.** Analysis answers an open question from documents and stops at the answer. Examples are a diagnostic, a gap register or a landscape brief. It ends in a recommendation, never a decision: the decision is yours.

*How this page grows: when a review finds a fault that is not on this page, add it here. Every later instruction of this kind then carries it.*

### 1. What the work chat refuses
1. **To call a proposal a decision, or to restate a governing document instead of quoting it.** Where the paper rests on a law, a strategy or the brief, it quotes the passage and says where it is.
2. **To make the case for one position without the passages that make the other strongest.** Each position is stated at its strongest, from the documents, before either is judged. The judgements go in one table, position by test, so that a fact counted against one and not the other can be seen.
3. **To count over a set it has not listed.** The set a test names, such as every requirement or every goal, is listed first from its own source. Then what was covered is set against it before a total or a zero is reported.
4. **To cite a source where it does not say what the paper says,** or to write a figure from anything but the passage that holds it.
5. **To contradict itself or the brief.** A figure given twice is the same both times. A departure from the brief is stated, with its reason.

### 2. What the review chat runs
- Every citation read at its source, against the sentence that cites it.
- The set each test names, listed again from its own source and compared with what the paper covers.
- The table of positions read test by test. Every fact a judgement rests on is looked up in the other position's cells.
- One figure of the paper worked out again by a route the paper did not use.

### 3. What you check before you issue the instruction
- The question is one you have not already decided, and the instruction asks for a recommendation.
- Every document the analysis rests on is in the material.
- Each set a test counts is named, with the source it is listed from.

## Drafting — the faults it refuses

**The kind.** Drafting writes a document that others will build on or receive. Examples are terms of reference, a decree, a business case or a note to a senior reader. Its content is settled by work already accepted. What is open is only whether it is written right.

*How this page grows: when a review finds a fault that is not on this page, add it here. Every later instruction of this kind then carries it.*

### 1. What the work chat refuses
1. **To supply a fact, a rule or a requirement the source does not carry.** It is a gap. It is raised against the source document, never filled in here.
2. **To close a review's gap only for the examples it names.** A gap that names three members of a set states a rule. The next version applies it to every member, and says how many still fail.
3. **To write for a senior or outside reader in working language.** The document uses the reader's words: no internal codes, no file names, no jargon of the project.
4. **To leave out a limit the record names, or to say more than the record carries, without saying so.** Every limit that an accepted document names is either in the draft or in the report's list of what was left out, with the reason. A limit of one step is stated as a limit of that step, not of the whole: a search that misses a child does not mean the system cannot find the child, if another step may find it. The draft's claims are listed, each with its source, before the draft is written.

### 2. What the review chat runs
- Every claim of the draft looked up at its source.
- Where a test asks for every member of a set, such as every limit the record names, the review lists the set itself from the same sources. It compares the two lists row by row and counts what is missing.
- For a document for an outside reader, a read for internal words and codes.

### 3. What you check before you issue the instruction
- The documents the draft rests on are accepted, and at the version you name.
- Where a test asks for every member of a set, the instruction names where the set is drawn from, and asks for it to be listed and counted before the draft.

## Checking — the faults it refuses

**The kind.** Checking establishes one figure or one fact, and reports it with its evidence. Examples are a count, a trace from requirements to goals, or a test on a running system. It changes nothing it checks.

*How this page grows: when a review finds a fault that is not on this page, add it here. Every later instruction of this kind then carries it.*

### 1. What the work chat refuses
1. **To trust a check's zero before the check has been seen to fail.** Plant the fault the check is meant to find, once, and see it caught. Only then is a clean result evidence of anything.
2. **To count over a set it has not listed.** List the set first from its own source. Counting both ways gives both totals and names every member that is in one and not the other.
3. **To report results as findings without reading each one against the file it came from.**
4. **To check a running system from memory or from its description.** A check of what a system does ends at the real thing, with the output kept.
5. **To change what it checks.** A defect is reported with its evidence, and becomes a candidate for a new instruction.

### 2. What the review chat runs
- The figure worked out again by a route the report did not use.
- The check repeated on another member of the set.
- The planted fault: the check given a case it must fail, and seen to fail.

### 3. What you check before you issue the instruction
- The set or fact to be checked is named, with the source it is listed from and its version.
- The instruction names the second route the review will use, so that the report cannot borrow it.
