# Module 5 — Join the blocks and prove the foundation

**Written for:** the team that configures the service (Architect register). **Videos:** 6.

**What it teaches.** What must be in place on the data exchange layer, which block holds the sequence, the once-only registration from beginning to end, its checks and its evidence.

**What you can do afterwards.** Say what must be in place before blocks can call each other, name the block that holds the sequence, run the once-only registration and read its evidence.

**What is built.** Configurations X1 to X7

## Subtopics

| # | Subtopic | Class | Demonstration | Single message |
| --- | --- | --- | --- | --- |
| [5.1](5-1.md) | What must be in place before the blocks can call each other | Core | Yes | Before one block can call another across ministries, each must be a member of the data exchange layer, each service registered with its contract, and access granted to the caller. |
| [5.2](5-2.md) | Who puts the steps in order: contracts, and the block that calls them | Core | — | The data exchange layer carries each call and enforces who may make it, but the registration service puts the steps in order, so know which block holds the sequence before you approve an integration plan. |
| [5.3](5-3.md) | The once-only registration, from beginning to end | Core | Yes | A learner signs in, the form fills with the facts the learner agrees to release, the registrar approves and the record is in the register: one run that proves four blocks work as one foundation. |
| [5.4](5-4.md) | The acceptance checks: from "set up" to "proven" | Core | Yes | Every configuration has a check that someone can run and read, and a block is called proven only when its checks have run and passed. |
| [5.5](5-5.md) | Reading the evidence of a call | Supplementary | Yes | Three records can show that a call took place, the message log, operational monitoring and the traffic view, but each only under settings you must choose before the first call. |
| [5.6](5-6.md) | What the next services can now use | Core | — | Identity, the learner register and payments are now services with published contracts that the next education services can use without building them again, with consent and notification still to add. |
