# The review of the application model

The record of a person's review of the application model, the one file from which the application is generated. The model itself is read by a program. This record is what the person reads, rules on and signs.

| | |
| --- | --- |
| **Document of the twelve** | 11 |
| **Who writes it** | The person who reviews the model, from the list of assumptions and losses that the assistant reports |
| **What goes in** | The application model, with the assistant's list of what it assumed and what it could not express |
| **Who accepts it** | The person who approves it, after reading what it assumed and what it could not express |
| **Taught in** | 4.4, 4.5, 4.6 |

## How to use this blank instrument

Copy this page into your own document. Fill in the answer to every line. Do not leave a line empty: write "none" where nothing applies, and where the answer is not yet known write an open question with the name of its owner and a date. Do not guess an answer to close a question. When the document is finished, give it to the person who accepts it, together with the questions at the end of this page.

## Every assumption

The assistant must refuse to guess. Where it assumed something, it names the assumption. Write one row for each.

| Line | What to write | Your answer |
| --- | --- | --- |
| **What was assumed** | In words | |
| **Where in the model** | The place | |
| **What the accepted documents say** | Or: nothing, which is a question and not an assumption to accept | |
| **Ruling** | Accept, correct the document that owns the fact, or reject; by whom and when | |

## Every loss

A loss is something an accepted document says that the model could not express. Write one row for each.

| Line | What to write | Your answer |
| --- | --- | --- |
| **What could not be expressed** | In words | |
| **Where in the documents** | The place | |
| **How it is handled instead** | Or: not handled | |
| **Ruling** | Accept the loss, change the document, or ask for another way; by whom and when | |

## Every refusal

A program refuses a model that contradicts what was accepted or breaks a rule of the platform. Write one row for each refusal met.

| Line | What to write | Your answer |
| --- | --- | --- |
| **What was refused** | In words | |
| **Why** | What it contradicted | |
| **How it was corrected** | Correct the document that owns the fact, then write the model again. Nobody switches the check off | |

## The approval

Write this once.

| Line | What to write | Your answer |
| --- | --- | --- |
| **Decision** | Approved; or adjustments asked, listed | |
| **By whom and when** | The person who approves | |

## Before you accept it

1. Is every assumption named, and has a person ruled on each?
2. Is every loss named, and has a person ruled on each?
3. Was every refusal answered by correcting the document that owns the fact, and not by switching the check off?
4. Does the model agree with the interaction design that was accepted?
