## Example output

**Tier design for the district term list (draft)**

| Tier | What happens | Detail |
| --- | --- | --- |
| Raw | The file is kept as sent | No change to any value |
| Bronze: mapping | Columns mapped | SchoolCode → school_code; PupilName → given_name; Surname → family_name; DOB → date_of_birth; Sex → sex (F/M → female/male); Class → grade (P4 → 4, *guess*); DateAdmitted → enrolment_date. Dropped: AdmNo, Remarks. Lacking: pnia_service_identifier and guardian identifier (may be empty); status (required, *guess: "enrolled"*) |
| Bronze: checks | Critical: required values, date written two ways, sex in the list, grade 1–12, age fits the grade, school exists | Message, for example: "The date is not written as year-month-day. Write it as, for example, 2015-03-21." |
| Staging | A PLR registry officer approves or rejects each passed row | Looks at possible matches with existing learners, and at the bronze report |
| Silver → gold | Approved rows merged; gold split into master (learners) and reference (schools, code lists) | Master records go into the register; the register gives each new learner a number |

**Open questions**

- Does "Class" always mean a primary grade, or do secondary schools send "F1"?
- May status be set to "enrolled" when the file does not say?
- How is a learner already in the register recognised, when the file carries no learner number?
- Is "repeat" in Remarks a fact the register should hold?

## Reading the output

### 1. The mapping and the approver follow the schema

Every source column is mapped or dropped, every schema field the file lacks is named, and the approver is a person, a PLR officer, as the tier layout specimen sets. The guesses are marked.

### 2. A default value is a quiet invention

Setting status to "enrolled" for every row writes a fact no school sent. It is marked as a guess, but a tired reviewer would accept it. The owner should decide; the safer rule is to ask the sender for it.

### 3. Matching is the hard part, and it is left open

Without a learner number in the file, the duplicate check cannot run on the key. The run lists the question but proposes no rule for matching on name, date of birth and school. That rule decides how many duplicates reach staging, and the owner must set it.
