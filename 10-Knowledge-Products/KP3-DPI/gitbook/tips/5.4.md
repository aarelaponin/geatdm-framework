## Example input

No check has run in Progressa. The output below is invented to show the shape of a failure; it is not a result.

**[country X]:** Progressa. **[the block]:** the learner register's write service on Linkup.

**[paste the full output]**, check X3, first call (with the grant):

```text
X3 call 1: registration service -> PLR write service, updateOrCreate
HTTP 500
{"type":"Server.ServerProxy.AccessDenied",
 "message":"Request is not allowed: SERVICE:PROGRESSA/GOV/PLR/LEARNER-REGISTER/plr-register"}
X3 call 2: member without a grant -> same call
HTTP 500  Server.ServerProxy.AccessDenied
RESULT: FAIL (call 1 refused)
```

**[paste it]**, the check's definition: "Make the write call from the registration service; make the same call from a member without a grant. The first call is answered; the second is refused."

## Example output

**To:** the owner of the learner register, PLR.

**1. What was run.** Check X3: the same write call to the learner register, once from the registration service and once from a member with no grant.

**2. What was expected.** "The first call is answered; the second is refused."

**3. What came back.** Both were refused. The first call returned:

> `"type":"Server.ServerProxy.AccessDenied", "message":"Request is not allowed: SERVICE:PROGRESSA/GOV/PLR/LEARNER-REGISTER/plr-register"`

The second call was refused as it should be.

**4. Likely cause (hypothesis, to confirm).** The grant on the write service does not name the registration service as the caller: it may be set for another client code, or at endpoint level on `exists` only.

**Question for the team that configured it:** which client, at which level, does the access list of `plr-register` name today?

## Reading the output

### 1. Earned: the failing line is quoted, not summarised

The note keeps the fault type and the service identifier exactly as the output gives them, and says plainly that half of the check behaved as expected. The owner can see at once that the refusal is the exchange's, not the register's.

### 2. Invented: the output itself

The output, the application code `LEARNER-REGISTER` and the service code `plr-register` are made up for this example; the build has not chosen them. Read this as a rehearsal of the note, never as a sign that X3 ran.

### 3. Check next: the second half proves little

Call 2 was refused, but so was call 1, so the refusal may come from something other than the grant, such as the service still being switched off after it was added. Ask for the security server's access list before anyone changes a grant.
