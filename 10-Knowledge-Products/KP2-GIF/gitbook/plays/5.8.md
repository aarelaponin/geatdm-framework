## Reading the output

### 1. The access-denied calls are read correctly

The run calls PLR's 38 refused calls a question, not an attack. That is right. In the build pack, PNIA's access list grants `identity-api` to PNEA alone, on purpose. So these refusals show the control working. What needs explaining is why PLR's system tried.

### 2. Five data points do not make a trend

"Latency rose fivefold" rests on one day's 95th percentile against another's. The first question also ties the failures to the latency as if one caused the other, and the data cannot show that. The compliance note holds back better: it names a threshold and asks for a second week before acting.

### 3. Check the input before trusting a clean run

These rows are invented. The build pack has the monitoring add-ons running on every security server, but no export and no collector. Central collection is one of the gaps it names. When you build the export, test it: the pack's services look a person up by NIN in the request path, and the monitoring records carry that path. Strip it before the data reaches any prompt.
