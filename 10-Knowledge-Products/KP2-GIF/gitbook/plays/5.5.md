## Reading the output

### 1. The approval step stays explicit

Step 3 approves each registration on the Central Server one by one, as the prompt asks. The pack's `federation-core.yaml` does the same (`management_request_approval: explicit`) and explains why: auto-approval would be unacceptable on a production Central Server. That step is the admission decision showing up in the configuration.

### 2. Step 2 does not follow the prompt's order

The prompt puts the anchor in step 2 and member registration in step 3. The run followed the pack's run book instead, which adds the members and subsystems on the Central Server before it publishes the anchor. Note the change, so no one "corrects" it back. The production notes are also more general than the pack's own list, which names the specifics: the fixed `xrd/secret` login, and message-exchange and OCSP ports that are never opened.

### 3. A run book is proved by running it

The pack records a timed deploy: on the run in `runbook.md`, about 9 minutes from zero to a running federation. But the acceptance files for the federation core and member registration still end with "UNVERIFIED until this passes on the live stack". Run step 4 end to end in your sandbox and record the result before you call this the build pack's run book.
