## Example input

**[country X]:** Progressa.

**From the federation run book (B32), in short:** the Linkup demonstration runs on one Docker host: a Central Server, four security servers (PDGA, PNEA, PLR, PNIA) and a Test CA, using about 11 GiB of memory. The member services are mock registries reading synthetic CSV files. The only network control is a loopback bind. The admin credentials are fixed by the test image. Operational and environmental monitoring add-ons run on every security server, but nothing collects their data. The SLA template states support Monday to Friday, 08:00–18:00 (illustrative).

**From the implementation plan (B28), in short:** four phases. Foundation (months 0–6): platform and trust anchor live, two pilot members. Pilot and Validation (7–12): first real once-only exchanges, five members. Expansion (13–18): fifteen members, twenty or more services. Optimisation (19–24): performance, the next sectors. The operator grows from 8–15 staff to 30–80.

## Reading the output

### 1. "The shape does not change" is earned

The build pack's own production-delta file says exactly this. It lists each demonstration shortcut beside its production need, and none of them touches a registration or a service description. Its conformance record agrees: of 75 clauses, 41 are implemented, 6 simulated, 24 named as absent and 4 out of scope. That record is a better start for this checklist than any list the assistant writes.

### 2. The phase column is a guess, and one row hides a legal question

The pack says only that the gap belongs in the multi-agency phase. The phase placed on each row is the run's own judgement. The CA row is the riskiest. Progressa has no e-transactions act, so an accredited certification authority may not exist yet. It may need a law or a procurement before Foundation can close.

### 3. The task the checklist forgets

None of the seven areas covers retiring the old links. Progressa's tax-to-business-register database link from 2022 still runs outside Linkup. The pack names this step: run the new exchange beside the old link, confirm they agree, move the consumers across, then switch the old link off. Add one row per agency. Also add the gates the pack names as absent, such as the admission decision and the monitored go-live. They are organisational, not technical, so this checklist leaves them out.
