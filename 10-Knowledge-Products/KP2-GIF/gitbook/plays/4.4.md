## Example input

The exchange, from the Use-Case Catalogue (B5), the first two rows (PNIA → PNEA: identity; PLR → PNEA: enrolment): PNEA pre-fills a certificate application from two registries. The shared entity is the **learner**: a person (PNIA) with an enrolment (PLR).

**Agency A, PNIA person register:** NIN (11 digits), FIRST_NAME, SURNAME, DOB, SEX (F, M), REGION. It also holds mother's name, birth registration number and address.

**Agency B, PLR enrolment register:** nin, school (the school's name), level (e.g. "Senior Secondary"), enrolment_year, status (active, transferred, completed).

**Vocabularies to align to**, from the standards portfolio (B22): CEDS for the person, OneRoster for the enrolment, ISCED 2011 for levels. GovStack's identity specification uses OpenID Connect claim names.

enrolment:             # anchor: OneRoster

    school:         PLR school     # OneRoster org [confirm: name or code?]

| Code list | PLR / PNIA value | Shared value |
| --- | --- | --- |
| Enrolment status | active | active [confirm] |
| Enrolment status | transferred, completed | active with an end date [confirm] |

**To confirm against the live registries**

- That every certificate applicant holds a NIN, and that no NIN is shared.
- The region code list, which PNIA and PLR may spell differently.
- Whether `school` can become a school code instead of a name.
- The status and sex translations above.

## Reading the output

### 1. The shape matches the build pack

The two entities, the CEDS and OneRoster anchors, the NIN key and the three OpenID Connect renames are all in the pack's `configs/semantic/semantic-map.yaml`. Mother's name, birth registration number and address are left out of the map, as the pack leaves them out. The draft did the fast part well.

### 2. "Unique" is not the risk; coverage is

The run treats the NIN's uniqueness as the open question. The bigger one is in A0 §3: PNIA issues child IDs only at 16. This exchange concerns senior-secondary candidates aged 16 and over, so it works. The same map applied to a primary-school learner has no key at all. Write that limit into the map before the next exchange reuses it.

### 3. School is a name, not an identifier

PLR returns the school's name as free text. Two schools with the same name, or one name spelt two ways, will not reconcile. The status translation is also a guess: OneRoster has no "transferred". Both need the data owners, not the architect, to decide.
