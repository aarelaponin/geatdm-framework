## Example input

**[country X]:** Progressa.

**From the federation run book (B32), in short:** a Central Server run by PDGA, the federation owner (`PROGRESSA/GOV/PDGA`). Four security servers: `ss-pdga`, `ss-pnea`, `ss-plr`, `ss-pnia`. A Test CA with OCSP and time-stamping. Three members: `PROGRESSA/GOV/PNEA:EXAMS` (the consumer), `PROGRESSA/GOV/PLR:ENROLMENT` (publishes `enrolment-api`) and `PROGRESSA/GOV/PNIA:IDENTITY` (publishes `identity-api`). The stand-up ends when every member appears in the Central Server registry. Synthetic learner data is then seeded into the two registries.

**From the data-protection envelope (B27), in short:** `identity-api` returns the NIN, given name, family name, date of birth, sex and region. It holds a mother's name, a birth registration number and an address, and does not return them. Only `PNEA:EXAMS` may call it. Lawful basis: a purpose-limited person lookup for issuing a credential (illustrative wording). `enrolment-api` returns school, level, enrolment year and status.

## Example output

**GIVEN** (technical, organisational): the federation is deployed and every member is registered. Both services are published with their access rights. Synthetic data is seeded, and the test picks a NIN that exists in both PNIA's and PLR's data. Every identifier below is *[confirm: against the live registry]*.

**WHEN** (technical): PNEA makes two calls through its own security server.

```
GET https://ss-pnea:2443/r1/PROGRESSA/GOV/PNIA/IDENTITY/identity-api/persons/{nin}
    X-Road-Client: PROGRESSA/GOV/PNEA/EXAMS
GET https://ss-pnea:2443/r1/PROGRESSA/GOV/PLR/ENROLMENT/enrolment-api/enrolments/{nin}
    X-Road-Client: PROGRESSA/GOV/PNEA/EXAMS
```

**THEN**

| # | Check | Passes when | Layer |
| --- | --- | --- | --- |
| 1 | Happy path | Both calls return 200, routed server to server (`ss-pnea` to `ss-pnia` and `ss-plr`) | technical |
| 2 | Right learner | Every returned field equals the seeded record for that NIN | semantic |
| 3 | Asked once | The assembled application holds one field from the citizen (the NIN) and nine from the bus. No field is keyed twice | organisational, legal |
| 4 | Only what the purpose needs | The identity response has its six fields and none of the three withheld ones | legal |
| 5 | Negative | The same identity call, sent as `PROGRESSA/GOV/PLR/ENROLMENT` through `ss-plr`, is refused by PNIA's access list with an X-Road access-denied fault, not a transport error | organisational |

**Evidence:** `out/application-{nin}.json`, the assembled application with the source of each field.

## Reading the output

### 1. The negative check tests the right thing

PLR is a member of the bus and publishes a service of its own, so its refusal shows that the access list did the work, not membership. The script also requires the refusal to come from PNIA's side as an access-denied fault. A timeout would look like a pass but prove nothing. The build pack's acceptance file records this denial as the X-Road fault `Server.ServerProxy.AccessDenied`.

### 2. "Legal" on check 3 is overstated

The script builds the application file and then checks that file. That proves no field was keyed twice in this form. It does not prove the learner was not asked on paper somewhere else. Check 4 tests that the response leaves out the withheld fields, but nothing in the script can test whether the lawful basis is real, and in the pack that wording is illustrative. Call the legal layer "enforced as configured", not "proven".

### 3. Two cases are missing

First, a NIN that PNIA holds and PLR does not should return the identity and a clean 404 from the enrolment service. A silent empty answer must not pass. Second, a plain-HTTP call to PNEA's security server should be refused, because PNEA's connection is set to HTTPS. The pack's script runs the first case as one of its six checks. Its acceptance file records the second refusal, but the script does not test it.
