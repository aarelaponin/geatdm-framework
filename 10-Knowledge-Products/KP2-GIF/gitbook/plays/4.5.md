## Example input

**Service brief:** PNIA's identity service. Given a learner's National ID number (NIN), return only the identity fields PNEA needs to issue a senior-secondary certificate. Provider: PNIA, subsystem IDENTITY. Consumer: PNEA, subsystem EXAMS.

**From the semantic map (B23), entity `person`:** key `nin` (string, 11 digits); `given_name`, `family_name` (string); `date_of_birth` (date); `sex` (F or M); `region` (string). Not in the map, so not returned: mother's name, birth registration number, address.

**From the standards portfolio (B22):** OpenAPI 3.0.3 for contracts; callers authenticated by X-Road, OAuth not adopted inside the bus.

## Reading the output

### 1. Minimisation lives in the contract

The response lists six fields and nothing else, because the semantic map stopped at six. This is the same contract as the build pack's `apps/specs/pnia-identity.openapi.yaml`. There, PNIA's record holds three more fields that never reach the bus. Data protection by design is visible here, in a file, not in a policy.

### 2. The 400 response was invented

The run added a 400 for a malformed NIN. The pack's contract declares only 200 and 404, and the brief gave no basis for it. It is plausible, but a consumer that codes against a 400 PNIA never sends will mishandle the real error. This is the kind of field the [confirm] marks exist for.

### 3. The forwarding URL is plain HTTP

`servers.url` is the hop from PNIA's security server to its own system, and it is `http`. The pack records this as an open production gap. The contract is where it becomes visible, so raise it here, with PNIA, before the description is registered.
