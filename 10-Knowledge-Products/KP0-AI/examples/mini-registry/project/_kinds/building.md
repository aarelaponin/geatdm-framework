# Building — the faults it refuses

**The kind.** Building makes a thing that runs: a prototype, a script, a page. Its content is settled by accepted documents, such as the requirements, the groundwork and the goal written in full. What is open is whether it runs as they say. Used in Module 5.

*How this page grows: when a review finds a fault that is not on this page, add it here. Every later instruction of this kind then carries it.*

## 1. What the work chat refuses
1. **To report a thing as running that it did not see running.** A screen is reported only after it was opened and checked in this round, with the output kept.
2. **To end a round without the project's checks**, each with its result. A build that compiles is not a build that runs.
3. **To test on a record the prototype cannot produce.** A test starts from data the prototype's own forms or made-up data would hold, never from a value nothing writes.
4. **To decide for every case what the instruction decided for one**, such as adding a retry or a default everywhere when one place was asked for.
5. **To repair a defect in the data or the groundwork it was not asked to repair.** It is reported, and becomes a candidate for a new instruction.
6. **To open a window on the screen.** Every check runs without one.

## 2. What the review chat runs
- The project's checks again, in its own run, with the result kept.
- One use of the screens, gone through as the person the goal is for, such as a school clerk.
- One way the goal can go wrong, set up and seen to be handled as the goal says.

A review of building that ran nothing says so in its first line, and does not accept.

## 3. What you check before you issue the instruction
- The documents it builds from are accepted, at the versions it names.
- Its first step, before anything is written, is to check that the tools answer and that the checks run on the project as it stands.
- Every file it will write or change is named, so that "write nothing else" can be kept.
