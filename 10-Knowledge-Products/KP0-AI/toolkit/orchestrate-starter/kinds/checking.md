# Checking — the faults it refuses

**The kind.** Checking establishes one figure or one fact, and reports it with its evidence. Examples are a count, a trace from requirements to goals, or a test on a running system. It changes nothing it checks.

*How this page grows: when a review finds a fault that is not on this page, add it here. Every later instruction of this kind then carries it.*

## 1. What the work chat refuses
1. **To trust a check's zero before the check has been seen to fail.** Plant the fault the check is meant to find, once, and see it caught. Only then is a clean result evidence of anything.
2. **To count over a set it has not listed.** List the set first from its own source. Counting both ways gives both totals and names every member that is in one and not the other.
3. **To report results as findings without reading each one against the file it came from.**
4. **To check a running system from memory or from its description.** A check of what a system does ends at the real thing, with the output kept.
5. **To change what it checks.** A defect is reported with its evidence, and becomes a candidate for a new instruction.

## 2. What the review chat runs
- The figure worked out again by a route the report did not use.
- The check repeated on another member of the set.
- The planted fault: the check given a case it must fail, and seen to fail.

## 3. What you check before you issue the instruction
- The set or fact to be checked is named, with the source it is listed from and its version.
- The instruction names the second route the review will use, so that the report cannot borrow it.
